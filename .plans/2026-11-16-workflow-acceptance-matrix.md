Leave the OpenAI subscription integration branch unchanged. The branch audit determines exact branch identities, ancestry and merge order; this matrix does not infer them from old plans.

## Functional findings to resolve

1. **Review detail query failures are not represented.** `reviews/$id.tsx` ignores the primary query's error and renders a skeleton whenever no data exists. A terminal 403/404/503 can therefore look like perpetual loading. A failed refresh can retain private cached text and old decision authority because completion errors are also ignored. Add current-query gating and visible recovery, preserve unfinished rationale during transient failure, remove private content on authoritative denial and disable execution/decisions until required metadata is current.
2. **Document detail and document drawer repeat that omission.** `documents/$id.tsx` and `DocumentDrawer.tsx` destructure only `data` from detail queries. Use the existing shared snapshot-retention policy and one small presentation contract; retain local input through outages, hide denied private content and gate dependent mutation/download actions. The server still enforces authorization; this finding concerns stale client disclosure/actions and recovery.
3. **Evidence prose contains superseded snapshots.** `design/acceptance.md` carefully records checkpoints but older entries can read like current status, including custom geometry superseded by the default radius policy. `PLANS.md` still claims the subscription flow has not merged even though the newer plan index states it merged through PR #10. Final release notes must state current integrated evidence and link historical records without promoting their status.
4. **Avoid broad refactoring before acceptance.** Template persistence belongs in core/contracts/db and already follows the audit path; immutable revisions, advisory commit locking, tenant checks, original-byte hashes, human-only decisions and staged-object accounting are substantive safeguards. Preserve them. Shared error/snapshot/feedback/draft helpers are useful reductions; rewriting the approval engine or collapsing distinct published/draft states would add risk and obscure the product contract.
