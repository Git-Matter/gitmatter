## One bounded recovery improvement

**P2 - Label each recovered scope with its earlier source identity.**

`apps/web/src/routes/_auth/documents/-components/PractitionerReviewPanel.tsx:135` renders earlier
scope drafts as bare paragraphs. The mobile capture shows an explicit warning that the text was
not applied to the current version, which is useful. However, after more than one source change,
the user cannot tell which earlier version produced each retained scope without relying on memory.
The underlying draft keys preserve version/head identity; the visible recovery list drops it.

**User effect:** a practitioner recovering interrupted work may consult the wrong earlier scope
while deciding what to inspect again. This is a recognition and recovery gap. It does not show a
bypass of the current-version confirmation or server token checks.

**Proportionate fix:** show each earlier scope beside its actual document version and change
identity, using an existing human-readable revision label when available. Keep it separate from
the current scope, and retain the warning and explicit current-document confirmation. Do not
auto-copy old scope text, imply approval, or add a new history interface for this deadline.

**Verify:** retain two different scopes across two source changes; confirm that each is visibly
associated with the correct earlier revision, the current field stays independent, and recording
still sends only the fresh current state token. Repeat at 390px and by keyboard. This case is
source-supported; the current capture contains only one earlier draft. It is a bounded follow-up,
not a reason to reopen the visual direction or hold unrelated demonstration work.
