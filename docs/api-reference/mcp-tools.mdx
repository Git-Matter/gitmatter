The connector at `/api/mcp` uses your assistant's own reasoning. It does not launch GitMatter LLM provider calls. Hosting and external research services may have separate costs. The built-in assistant also uses this shared catalog, with additional provider-funded tools.

Read source documents, create a review (or prepare one with `run_playbook`), then populate findings with `write_cell` and exact source quotes. Document edits remain proposals until a person accepts or rejects them in GitMatter. Review cells record agent findings; they are not human approvals.

The combined catalog below contains 52 tools. Legal research availability depends on jurisdiction. After an update, refresh your client's tool catalog or reconnect if it still shows removed tools. `run_cell` and `draft_playbook` are available through the built-in assistant, not this subscription-only connector. `resolve_document_edit` is reserved for people in the UI.

## `propose_document_edit`

Propose tracked changes (find -&gt; replace) on a document. Pass ALL edits for this document in a single call via the `edits` array — they land as one version the user accepts or rejects. Keep each `find` to the exact minimal substring being changed; anchor it with `contextBefore`/`contextAfter` (~40 chars of surrounding text, copied verbatim) so the location is unambiguous. The document is unchanged until accepted.

Inputs: `documentId`, `edits`.

Changes workspace data; recorded under the acting account.

## `run_playbook`

Prepare a review from an approved playbook with one verdict column per rule. Supply reviewInstructions to capture the represented party, disclosure role, NDA structure, business purpose and governing law; null/unknown means not known. These instructions are frozen in the review. This creates pending cells; it does not run a model. Read each document with get_document, analyse it yourself, then save cited findings with write_cell. Read results with read_review_cells and get_review_completion.

Inputs: `playbookId`, `requestId?`, `reviewInstructions?`, `documentIds`, `matterId?`.

Changes workspace data; recorded under the acting account.

## `write_cell`

Write your own extracted value into one review cell — for when you have read the document yourself and produced the answer. Committed under your name. This does not run a GitMatter model or require an LLM API key. Supply exact source quotations; page numbers are omitted because current review snapshots have no trusted page map. flag is the RAG status: green=ok, yellow=caution, red=problem, grey=n/a.

Inputs: `reviewId`, `documentId`, `columnIndex`, `summary`, `flag`, `outcome?`, `reasoning`, `citations?`.

Changes workspace data; recorded under the acting account.
