Before sending confidential material, check which services receive it and which terms apply. This page covers gitmatter's built-in AI requests, connected assistants, and provider retention controls. gitmatter stores your documents and work history separately from any AI provider.

<Callout type="warn">
  Provider policies change. The provider summaries below were reviewed on November 16, 2026. Verify
  your service, model, account controls, and agreement before relying on a retention claim.
</Callout>

## What gets sent to a provider

Built-in chat and tabular review send prompts and document context to the service serving the selected model. OpenRouter is an intermediary that forwards requests to a model provider. Research and external tools can send requests to other services, each with its own data policy.

When you connect ChatGPT, Claude, or another external assistant, it receives the gitmatter tool results it requests. Its service terms and settings govern that content. A provider API agreement for gitmatter's built-in AI does not establish the connected assistant's retention policy.

## Whose key is used

A provider key authorizes requests under an account with the AI service. gitmatter uses your saved key first, then a server-wide key if configured. The model catalog reports the active source as `user` or `env`. If a run has no requested model, gitmatter selects an available configured model.

Removing your saved key can make a server key active. Revoking a key at the provider blocks future requests authorized by that key; it does not cancel requests already in progress or disable other providers and connected assistants.

## Per-provider retention posture

Training, response storage, abuse monitoring, and metadata retention are separate policies. Zero data retention (ZDR) is a provider arrangement with defined scope and exceptions. gitmatter does not verify your account's ZDR eligibility or agreement.

| Service               | What to verify                                                                                                                                                                                                                                                                                                                                                          |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OpenAI API**        | API content is not used for training by default. Abuse-monitoring logs can be retained for up to 30 days. ZDR requires approval and has endpoint and feature limits. See [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data).                                                                                                               |
| **Anthropic API**     | Standard API inputs and outputs are deleted within 30 days, subject to exceptions. ZDR depends on the agreement, model, and feature. See [commercial retention](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data) and [API retention eligibility](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention). |
| **Google Gemini API** | Paid-service terms exclude prompts and responses from product improvement but permit limited safety logging. Unpaid-service terms can permit content use and human review; regional exceptions apply. See [Gemini API terms](https://aistudio.google.com/docs/terms).                                                                                                   |
| **OpenRouter**        | Review both OpenRouter's handling and the routed endpoint's policy. ZDR enforcement can allow Safety Retention endpoints depending on account and guardrail settings. See [routing controls](https://openrouter.ai/docs/guides/routing/provider-selection) and [ZDR scope and exceptions](https://openrouter.ai/docs/guides/features/zdr).                              |

## What gitmatter sends today

The adapters send these request controls:

- **OpenAI:** `store: false` disables response application-state storage for the request, subject to feature-specific rules. It does not disable abuse-monitoring retention or establish ZDR. The adapter requests encrypted reasoning for replay across tool turns.
- **OpenRouter:** `provider.dataCollection: "deny"` filters endpoints under OpenRouter's data policy. The adapter does not send an explicit `zdr` flag or verify account and guardrail retention settings.
- **Anthropic and Gemini:** the adapters do not send a ZDR control. Account agreements and service policies govern retention. The Gemini adapter uses the Gemini API with an API key; it does not configure Vertex AI.

## Before sending confidential content

Confirm the applicable account controls with your provider:

- **OpenAI and Anthropic:** verify any approved ZDR arrangement and the selected model and feature's eligibility. A saved key alone does not establish coverage.
- **Gemini:** confirm the Cloud project's billing status and applicable data-use terms. gitmatter does not check paid-service eligibility or reject a key based on billing tier.
- **OpenRouter:** review account and guardrail ZDR settings, including whether Safety Retention is allowed. Its `zdr: true` request option is not sent by gitmatter today. Provider definitions also have exceptions and caching rules; avoid promising that nothing is ever retained.
- **Connected assistants and external tools:** verify their policies separately from the built-in API path.

## User controls

- Pick the model (and therefore the provider) per chat message and per review run.
- Add or remove provider keys in Settings &rarr; AI &amp; Models.
- Removing a saved key can make a configured server key active; it is not a global AI off switch.
- Organization admins can export selected client and matter fields, review grids, and a document metadata manifest in Settings &rarr; Data &amp; Privacy. This excludes document files and versions, chats, workflows, commit history, and security audit logs.
- Account deletion does not establish complete removal of shared organization records, stored files, or backups. See [data retention](/admin/data-retention) for cleanup behavior.
