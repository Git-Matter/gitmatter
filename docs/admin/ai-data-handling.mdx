Matter documents may contain confidential, personal, sensitive, or privileged information. Before using AI with them, establish that the particular account, service terms, settings, and processing route are appropriate for your practice and that use of the material is authorised.

<Callout type="warn">
  Supplying an API key, paying for an AI subscription, or selecting an Australian document-storage
  region does not establish zero retention or suitability for client information. Verify the current
  provider terms and your account's configuration before relying on either.
</Callout>

## Two ways to use AI

### Connect your own assistant

An external assistant such as ChatGPT or Claude connects to gitmatter over MCP and calls the tools your account can access. The assistant may receive document content in tool responses. That assistant's own account terms, conversation history, retention settings, connected tools, and processing locations apply separately from gitmatter.

gitmatter records the actions performed through its tools. It does not automatically hold a complete transcript of a conversation conducted in an external assistant. A paid consumer subscription is not evidence of an enterprise confidentiality or zero-retention agreement.

### Use gitmatter's built-in features

The built-in assistant and review features send prompts and relevant document content to the provider serving the selected model. OpenRouter is an intermediary: requests through it also reach the model-serving provider. Research tools can send queries to their own sources, including CourtListener and IP Australia. Review the selected tools as well as the model before using client details in a request.

For each AI provider, gitmatter uses your saved key first, then a configured deployment-level key if one exists. The model picker indicates the active source. A personal key identifies and bills your provider account; it does not itself establish a retention agreement.

## Controls implemented in the provider adapters

| Route               | Application setting                          | What still needs checking                                                                                                                                                              |
| ------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenAI              | `store: false`                               | This disables response storage requested through that parameter. It does not establish the absence of abuse-monitoring logs or an account-level zero-retention agreement.              |
| OpenRouter          | `provider.dataCollection: "deny"`            | A routing preference is not evidence of the actual account agreement, endpoint eligibility, or every intermediary's handling. Verify the route and any stricter retention requirement. |
| Anthropic or Google | Requests use the configured provider account | Check the applicable product, account tier, retention, training terms, and any additional agreement. Do not infer them from the key or model name.                                     |

Provider policies and product availability change. This guide deliberately does not promise a retention duration for an account that gitmatter cannot verify. Consult the applicable provider's current documentation and contractual terms:

- [OpenAI API data controls](https://platform.openai.com/docs/guides/your-data)
- [Anthropic privacy documentation](https://privacy.claude.com/)
- [Gemini API terms](https://ai.google.dev/gemini-api/terms)
- [OpenRouter privacy policy](https://openrouter.ai/privacy)

## Storage region and processing location are different

The hosted document-region choice routes document object storage. It does not locate the account database, extracted text, audit events, backups, email, error monitoring, AI requests, or an external assistant's conversations. Governing law is a separate matter setting.

Retain the application record and the relevant provider/deployment evidence when documenting a location requirement. See [privacy evidence](/admin/privacy-evidence). Do not describe an Australian document-storage choice as proof that all information is processed or retained only in Australia.

## A practical setup check

1. Choose the AI execution path and identify the actual account and provider route.
2. Review current contractual terms, training use, retention, processing locations, and account permissions for the intended material.
3. Check the selected document-storage region separately from the other systems involved.
4. Start with the fictional sample. Verify source checking, output quality, and the Word handoff before deciding whether to use client material.
5. Keep the evidence supporting your configuration decision and review it when the provider or account changes.

Never send credentials or confidential material in a setup enquiry. Add provider credentials only through the application's designated settings. [Assisted setup](/admin/assisted-setup) explains the available paths.

## User controls

- Select the model and available research sources in the assistant.
- Add or remove provider keys in Settings → AI & Models.
- Connect and manage an external agent through Settings.
- Review document-storage evidence and available export/deletion controls in Settings → Data & Privacy.
- Check the [data retention policy](/admin/data-retention) for data retained by gitmatter itself; provider retention is separate.
